## Introduction

OWASP's mission is to help the world improve the security of its
software. Open source projects produce software that everyone else
relies on, so OWASP encourages them to use automated security testing
to improve the security and quality of their code.

Many types of tools can help, and a number of vendors offer their
products free or at no cost to open source projects. Check each
product's own terms for what is available to open source projects.

## Types of Tools

  - [Static Application Security Testing (SAST)](Source_Code_Analysis_Tools) - analyses source code or compiled code for security flaws.
  - [Dynamic Application Security Testing (DAST)](Vulnerability_Scanning_Tools) - tests running applications, primarily web applications.
  - Interactive Application Security Testing (IAST) - analyses an application while it runs, primarily for web applications and web APIs.
  - [API security tools](api_security_tools) - tools designed for APIs.
  - [Component Analysis / Software Composition Analysis (SCA)](Component_Analysis) - identifies open source and third-party components and their known vulnerabilities. Keeping open source libraries up-to-date also reduces the risk of [Using Components with Known Vulnerabilities (OWASP Top 10 2017 A9)](https://owasp.github.io/www-project-top-ten/2017/A9_2017-Using_Components_with_Known_Vulnerabilities.html).
  - Static code quality tools - code quality has a significant correlation with security.
  - Security tools built into DevOps/CI environments.
  - Secrets detection tools.
  - Automatic remediation tools.
